# PostgreSQL migrations

The PostgreSQL chain is independent from `pkg/storage/sqlite/migrations`; the
SQLite migration files are released, immutable, and never replayed against
PostgreSQL.

- `000001_postgres_baseline.sql` is a squash of the released SQLite schema at
  migration `000020`. It is immutable after release.
- Every later migration uses the **same six-digit version and name** as its
  SQLite counterpart (for example `000021_add_x.sql` in both directories).
  `TestPostgresMigrationsPairWithSQLite` enforces the pair.
- `TestPostgresSchemaParityIntegration` compares the final SQLite and
  PostgreSQL table/column/index shapes and fails on drift.
- The runner applies pending files in one transaction under
  `pg_advisory_xact_lock(hashtext(current_schema()))`; concurrent daemon starts
  serialize and the second one sees the committed history.
- `schema_migrations` is created by the runner, not by a migration file.
- Translate SQLite types as follows: `INTEGER` → `BIGINT`, `TEXT` → `TEXT
  COLLATE "C"`, `INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGINT GENERATED BY
  DEFAULT AS IDENTITY PRIMARY KEY`, and `strftime('%s','now')` defaults →
  `floor(extract(epoch from now()))::bigint`. Keep boolean columns as
  `BIGINT` 0/1 and timestamps as integer Unix values; the Go scanners depend on
  that representation.
- Foreign keys must be created in dependency order (the parity test checks the
  final shape, not the order).
